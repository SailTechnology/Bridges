# 首次配对与日常部署

## 工作方式

```text
Neo 上的 GPT
   │ 读取必要文件 / 提交固定构建任务
   ▼
Windows 文件工具 → 原工程只读输入 → H: 独立构建目录
   │ 最终 ZIP + 版本与 SHA-256
   ▼
Neo 校验 → 安装到新目录 → 启动 / 检查
```

NAS 和云端聊天同步不参与此流程。两端不用共享 GPT 账号。Windows 必须开机、联网，构建任务使用已有 Windows 工具链。

## Windows 端只需准备一次

默认配置不启用远程网络。以下首次准备命令均在 Windows PowerShell 执行，已运行的文件工具会直接复用。

1. 生成仅针对章鱼工程的配置。这会先备份 Bridges 自己的旧配置，不修改源工程和 Codex 账号配置。

```powershell
& 'H:\Projects\Bridges\scripts\Prepare-FileBridge.ps1'
```

2. 启动本地文件工具。

```powershell
& 'H:\Projects\Bridges\scripts\Start-Bridges.ps1'
```

3. 在需要远程访问时启用已有 Tailscale 的私网 HTTPS 入口。

```powershell
& 'H:\Projects\Bridges\scripts\Enable-Tailscale.ps1'
```

脚本先检查 8443 是否已有其他服务，不会覆盖它们。不使用 Funnel，不公开到互联网。如果 Tailscale 要求首次启用 HTTPS，按其官方页面完成；不要关闭证书验证。已启用后的地址以 `tailscale serve status` 为准。

4. 打开 `http://127.0.0.1:8877`，点击“连接 Neo”生成一次性配对码。Neo 加入同一个私人 Tailscale 网络后进行配对。

远程访问与自启动相互独立。本机已运行 `Install-Autostart.ps1`，设为当前用户登录后后台启动；程序仍会受 Windows 休眠状态影响。以后迁移到其他 Windows 时，可运行同一个脚本安装此入口。

## Neo 首次配对

在 Neo 直接拉取公开仓库，无需 GitHub 账号：

```bash
mkdir -p ~/Projects/Bridges
git clone https://github.com/SailTechnology/Bridges.git ~/Projects/Bridges/接入工具
```

如果该目录已经存在，先核对来源和本地改动，不要覆盖。ZIP 方式仍可解压到同一位置。随后在 Neo 上执行：

```bash
/bin/bash ~/Projects/Bridges/接入工具/macos/bridges-client.sh setup https://sailstation.tail416821.ts.net:8443
```

2026-11-10 已由 Neo 实际读到此地址的健康接口。配对前先更新工具，并确认健康接口版本至少为 `0.2.0`。按提示在 Neo 终端隐藏输入一次性配对码，不在聊天里粘贴它。

配对码本身十分钟有效、单次使用；配对完成后的设备授权永久有效，直到在 Windows 手动撤销。Neo 将独立设备令牌保存在本机私有目录的 `device-auth.curl`，文件权限为 600；Windows 只保存令牌哈希。它不受七天或闲置到期限制，重启服务、重启 Neo 和更新工具均不需要再次输入。

浏览器 Cookie 是另一种保存方式，访问时滚动延长浏览器保留时间；命令行和桌面入口使用独立永久令牌，不依赖浏览器 Cookie 的保留期限。旧版尚未过期的配对 Cookie 可由新版 `setup` 自动升级为永久令牌，无需新配对码。

客户端对私网和本机地址的请求绕过 HTTP 代理，HTTPS 证书仍正常校验。使用域名连接时，Neo 需要启用 Tailscale DNS；这与 GPT 使用的代理或账号无关。

## 日常只需一句任务或一条命令

告诉 Neo 的 GPT：“使用 Bridges 部署今天的章鱼地面站”。

```bash
/bin/bash ~/Projects/Bridges/接入工具/macos/bridges-client.sh deploy octopus-groundstation
```

客户端自动完成提交、查询、下载、SHA-256 校验、安装和请求启动。安装目录带有任务 ID，不覆盖旧应用。旧服务已在运行时，新版保留在独立目录，暂缓启动；GPT 应检查设备状态后再处理切换。

也可以首次安装一个桌面入口：

```bash
/bin/bash ~/Projects/Bridges/接入工具/macos/安装一键部署入口.command
```

安装后，双击桌面“部署章鱼地面站.command”，自动复用授权执行同样的部署。入口本体在 `~/Applications/Bridges`，随 Git 仓库内脚本更新生效。安装脚本保留同名的其他文件，更新自己的旧入口时先备份。

日常不运行配对向导，不需要输入配对码。授权无效时部署会停止并提示；网络超时时则保留授权，待连通后重试。

构建脚本发生变化时，任务会报错停止。先核对变化，再重新运行 Windows 配置准备脚本更新脚本哈希。不要为了追求自动化跳过脚本核对。

## 故障与恢复

- 连接失败：检查 Windows 是否开机、Bridges 是否运行、两端 Tailscale 是否在线。客户端不会改用公网或另一个账号。
- 如果健康接口在 Windows 本机返回正常、Neo 却超时，可检查 `tailscale debug prefs` 中的 `ShieldsUp`。本次故障即由它阻断，已用 `tailscale set --shields-up=false` 修复，Neo 已确认连通；没有关闭 Windows 防火墙或修改全局访问规则。
- Windows 本机打开 `http://127.0.0.1:8877`，点击“已授权设备”可查看或撤销设备。撤销后原设备令牌和 Cookie 都失效，其他设备不受影响。重新接入才需新配对码。
- 授权文件丢失或被清除：重新首次配对。不要为处理网络超时而删除授权目录。
- 构建失败：源工程保留，错误日志和任务目录留在 H:；不会自动重发构建或覆盖旧部署。
- 下载中断：再次执行 `download <任务ID>` 可继续下载；成品必须通过 SHA-256 才能安装。
- 新版不能启动：旧应用、旧目录和应用数据仍在。可以直接打开旧应用；本工具不自动删除历史版本。
- 停止文件工具：运行 `H:\Projects\Bridges\停止工程联动.cmd`。关闭页面不等于停止服务。
